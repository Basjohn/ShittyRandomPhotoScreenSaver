# Audit, 14 Nov 2026: the N2.5 merge (b8457c3c, native Spectrum on the composite, ABI 8)

Scope: `git diff b8457c3c^1 b8457c3c` (71 files) and its branch commits. Read-only on product code. Opus 5.5, audit
slot. No build, no load, no window on a real screen. The module is not built in this worktree, so the module tests
(`test_native_core_spectrum_program.py`, `test_native_core_packet_reader.py`) skip here. The GPU-free files pass
(`test_shader_derivatives`, `test_native_visualizer_route`, `test_native_core_spectrum`, `test_native_program_values`,
`test_backend_availability`: 35 passed). Two probes were written for this audit and deleted afterwards. Their output is
quoted below.

Counts: **1 high, 4 medium, 9 low.**

## Verdict on the parts asked about

- **Render-thread lifetime.** Sound. A reader is read only in `SpectrumSource::sync()`, called from
  `CompositeItem::updatePaintNode` with the GUI thread blocked. `bind`/`unbind` move the current reader to
  `m_retiring` under `m_mutex`, and `releaseRetired()` (the retire job) runs first in every sync and in the node's
  destructor (render thread, QRhi alive). If no node ever existed, the source's destructor releases on its last owner's
  thread, and no read can be in progress there. The item's destructor unbinds and never waits. Teardown order against
  the barrier: `QuickSceneController._retire_qml_objects` (the only caller of `close_native_route`,
  `scene_controller.py:3684-3687`) runs only after scene-graph invalidation (`:3078-3091`, `:3658`). By then Qt has
  deleted the composite's node on the render thread, so the source's last release is on the GUI thread with no reader
  active. No Python thread state is touched on the render thread: the sync path is pure C++, and `ThreadProbe` counts
  it.
- **The `packet_reader_close` reference scheme** (`module.cpp` `ReaderEntry`, `dropReference`) is memory-safe.
  `packet_reader_resume` only touches `closing` under `closingMutex`, and `dropReference` removes the entry under the
  same mutex before it deletes it.
- **Backend gating.** Spectrum on Vulkan comes from `renderer_backends`. `test_vulkan_offers_exactly_the_modes_the_route_draws`
  holds the registry and `NATIVE_MODE_IDS` to one set, with a control. `has_studio` adds `STUDIO_PREVIEW_BACKENDS`, so
  on Vulkan no Studio is offered, the card glyph (`display_manager.py:1045`) included. The Studio's mode switcher drops
  greyed modes. All of this is consistent.
- **The shader change** is the hoist plus three deliberate changes to the OpenGL reference itself. `fwidth` became
  `fwidthFine`, the corner arc tests became `precise` (no FMA), and the pixel now comes through `fragPixel`/`u_window_from_target`
  (identity on OpenGL). The hoisted prologue is safe for discarded lanes: `bar_slot` is clamped before the array reads,
  and a zero `step_x`/`step_y` only feeds lanes the same uniform test discards. The discards are the original tests,
  in their original order.

## High

### H1. At common fractional scales the card's window map raises, and the native Spectrum never draws

`rendering/native/spectrum.py:54-70` (`compose_window_from_target`), called from `:111`. Inputs come from
`window_metrics` (`:130-138`) via `NativeVisualizerRoute.card` (`rendering/quick/visualizer/native_route.py:197`,
`:218-230`).

The composed target-to-window map is checked for whole-pixel coefficients with a tolerance of 1e-3. Its scale comes
from the window map, which uses `window_pixels / window.width()`, but the target map uses `dpr`. Under `PassThrough`
(`main.py:1124`), Qt's logical window size is the rounded `device / dpr`. When `device / dpr` is not an integer, the
two scales differ. The offset term then misses a whole pixel by about `(card x + target x) * (vw/W - dpr)`, which is
tenths of a pixel for any card away from the left edge. Probe (a card at about 1200 device px):

```
1920x1080@100%                     OK
2560x1440@125%                     OK
2560x1440@150% (logical 1707x960)  RAISES ... [0.9998047256395233, 0.0, 1201.7652802187072]
3840x2160@175% (logical 2194x1234) RAISES ... [1.0001302252897513, 0.0, 1202.656595910926]
```

**Failure scenario.** The saver runs on Vulkan on a 2560x1440 display at 150%, a very common setup.
`VisualizerRenderItem.update()` calls `route.sync()`, then `card()`, then `spectrum_presentation`, which raises
`ValueError` on every update request. The exception escapes `update()` (`item.py:287-305`) into whatever owner path
asked for the frame. Spectrum, the only mode offered on Vulkan, never draws. The parity runs used windows whose
logical size times dpr is exact (`test_native_core_spectrum.py:47` uses 1920x1080 at 1.5), so nothing covered this.

The same mismatch affects `composite_geometry(..., quad_aligned=True)` (`rendering/native/composite.py:40-50`). It
places the target on "whole device pixels" using `dpr`, not the window's real logical-to-pixel ratio, so on such a
display the target's edges and its 2x2 quads are not the window's.

**Suggested fix.** Build the target-to-window rows from the window's real pixel ratio (`window_pixels / window_size`
per axis, the ratio Qt's projection uses), or directly from the target's device-pixel origin in the window's
framebuffer. Do not compose with `dpr` and re-round. Decide placement (`_on_device_grid`) with the same ratio. Make
`route.sync` fail closed: log once, hide the composite, never raise out of `update()`. Add a test that runs
`spectrum_presentation` at 2560x1440@150% and 3840x2160@175% (logical 1707x960 and 2194x1234), and confirm on Display 1
at a fractional scale in N2.8.

## Medium

### M1. The route's failure paths do not fail closed (native_route.py)

- `bind` (`:89-112`) creates and maps the frame mapping (`:96-100`) before `spectrum.bind(...)` (`:109`). If the bind
  raises (a mapping the reader refuses, a schema-table mismatch in `core.spectrum()`), `_identity` stays None.
  `self._memory` and `self._writer` stay set, and the next `sync` calls `bind` again. `unbind()` returns early because
  `_identity` is None, so the previous mapping is overwritten without `writer.release()`/`close()`/`unlink()`. That
  leaks one named mapping per update request while the failure lasts.
- If `self._spectrum.program(mode_fragment_pack(mode_id))` raises (`:105-108`, for example a frozen build without
  `spectrum.frag.qsb`), `self._spectrum` is already set, so the program is never retried. The item then has no
  program: `SpectrumContent::ensure` fails on every frame (M2), and the screen is blank with no Python-visible error.
- Any exception in `sync` (H1, `window_metrics`' `RuntimeError` when the host has no window, a refused settings
  `ValueError`) propagates out of `VisualizerRenderItem.update()`.

**Suggested fix.** Order `bind` as: program and core bind first, mapping second, with cleanup on failure. Make the
route's failures one fail-closed state: logged once, composite hidden, nothing retried per update. Test each path.

### M2. A failed content record is retried every frame (surfaces.cpp:258-259; spectrum.cpp:807-810, 821-836, 869-871)

`Surface::record` returns false when `SpectrumContent::record` fails, and leaves the surface dirty. The frame driver
(`frame_driver.cpp:366-371`) calls `setError` and moves on. On the next frame the surface records again. `ensure()`
then rebuilds `Resources` (three buffers and two bindings created, the pipelines fail, everything freed) and
`primeForLoad` records again. The load pass explicitly avoids this ("dropped at the next edge, never retried every
frame", `frame_driver.cpp:359`).

**Failure scenario.** The program is missing (M1), or a pipeline is refused on a driver. QRhi objects are then created
and destroyed every frame while the window renders, the error is overwritten every frame, and the Visualizer is blank.
That breaks "nothing per frame" and gives no single failure edge.

**Suggested fix.** On a content failure, mark the content failed until its input changes (new program, new target,
new pass descriptor), record once, and report the failure through the source's state. Add a test with a pack whose
pipeline cannot be created, or with no program.

### M3. Spectrum's settings arithmetic has two owners (implementations/spectrum.py:480-531 vs `render`, :265)

`spectrum_settings_values` re-implements the settings half of `QuickSpectrumRenderer.render` ("the same helpers, the
same arithmetic"), but `render` does not call it. The guarding test
(`test_native_program_values.py:68-112`) compares the two on one frozen snapshot only: quarters 0, not expanded, one
style (single piece, radius 0) and the frozen preset's glow, ghost and rainbow flags. A later edit to `render` (a
clamp, a new decor branch, a member resolved differently under segmented mode or a non-zero radius) that misses
`spectrum_settings_values` changes OpenGL and leaves Vulkan drawing the old value, and the test stays green unless that
one snapshot exercises it. This breaks "fix at the owner, one contract".

**Suggested fix.** Make `render` build its settings members through `spectrum_settings_values` (one owner) and keep
only the frame members and the GL upload in `render`. Until then, parametrise the test over quarters 0-3, expanded,
segmented, a non-zero radius, and glow/ghost/rainbow on and off. Derive each variation from the spec, not from preset
values.

### M4. The route's own logic has no test (tests/test_native_visualizer_route.py)

The tests drive `VisualizerRenderItem` with `_RecordingRoute`. `NativeVisualizerRoute.sync`, `bind`, `unbind`
and `close` are untested in pytest:

- the card, settings and placement change caching (`:192-204`);
- the publish with identity and flags (`:205-215`);
- the mapping's `close`/`unlink` at unbind (`:126-135`);
- the composite's destroy at close (`:143-145`);
- the `_hide` path.

They are exercised only by `tools/visualizer_replay/owner_render_parity.py --native`, a tool. M1's leak and H1 would
have shown in such tests.

**Suggested fix.** Add tests with a stand-in core (as `test_the_face_speaks_the_modules_entries` does) for:

- the publish on a new snapshot only;
- no re-send of an unchanged card or settings;
- unbind closing and unlinking the mapping;
- close destroying the composite;
- the bind-failure path (M1).

Include a negative control for each.

## Low

- **L1. `spectrumBlock` trusts `bars_len`/`peaks_len`** (`spectrum.cpp:378-383`). It writes `logicalBars[i]` for
  `i < bars_len` into a 64-entry stack array and reads past the record. The product reader refuses anything over 64
  (`frame_abi_generated.h:112,114`, `AtMost 64`), but `spectrum_block` (any bytes from Python) and the
  `skip_head_check` control reach it unchecked. That is a stack overflow on the render thread under a harness control.
  Clamp both to `kMaxBars` and to the field's capacity.
- **L2. `program_blocks` edge cases do not fail closed.**
  - `unfilled()` skips members with `components() == 0` (`program_blocks.cpp:194`). A `mat3`, `mat2`, `double` or
    struct member added to a shader is then neither packable nor reported: it draws as zeros, contrary to the header's
    "reports a member nobody filled".
  - `arrayDims.first()` (`:81`) takes only the first dimension of a multi-dimensional array.
  - An out-of-range write is skipped silently while the member is marked filled (`:152-155`).
  - `qint32(value)` (`:24`) is UB for NaN or out-of-range doubles reaching an int member through `set()`.
  - `setJson` accepts a bool scalar but refuses bools inside arrays (`:168-174`).

  Fix: refuse unpackable members at `reflect`, or list them in `unfilled()`; refuse multi-dimensional arrays; fail a
  write that does not fit; clamp or refuse non-finite values for ints. Add a GPU-free unit test of
  `BlockLayout`/`BlockValues` (stride inference, partial arrays, int vs float, `mat4`).
- **L3. Settings are re-packed from JSON on every record** (`spectrum.cpp:454-456`). `spectrum.h:121-122` says
  "re-packed only when they change". Nothing runs at rest, but every played frame parses about 40 JSON members on the
  render thread. Fix: pre-pack a base `BlockValues` when the settings are taken in `sync`, and copy it per record.
- **L4. `setProgram` drops the settings** (`spectrum.cpp:562-567`: `m_program = program`, with empty settings). The
  route caches `_settings` (`native_route.py:201-204`), so after a second `program()` call it would never resend
  unchanged settings, and the item would draw unfilled zeros. Not reachable today (the route sets the program once).
  Fix: keep the settings across a program change when they still validate against the new layout, otherwise refuse.
- **L5. `tests/test_shader_derivatives.py` misses four undefined-derivative shapes.** Probe output, each "NOT
  REFUSED": a helper with an early `return` before its `fwidth`; a derivative inside a non-uniform `if` in `main`; a
  non-deriving helper that discards, called before `main`'s derivative; an implicit-LOD `texture()` after a discard.
  Spectrum has none of them today, but the guard is the stated gate for every later port (Oscilloscope, Bubble and
  Spline Curve are next). Extend `late_derivatives` and add a negative control for each.
- **L6. `renderer_prepared` is True at once on the native route** (`item.py:316-323`). The native pipeline (Vulkan
  pipeline creation for a large fragment shader) is built at the first record, which is the reveal frame. That runs
  against the gradual warm-up rule. Fix: create the content's pipeline at bind on the render thread (one unit on an
  already-rendered frame) and report prepared from the source's state.
- **L7. The onedir post-build check asserts only `.frag` files** (`tools/build_layout.ps1:793-800`, `:819-837`). The
  shipped `spectrum.frag.qsb`, which the native core loads at run time, is checked only at source preflight
  (`build_runner.py:1193`). Fix: assert each `NATIVE_MODE_IDS` mode's `.qsb` in the payload.
- **L8. The native objects are invisible to the destruction barrier.** If the Visualizer item was already deleted
  (the logged path at `scene_controller.py:3056-3064`), `close_native_route` is skipped (`:3685`). The route's
  `SharedMemory` then lives until GC and its composite goes with its C++ parent, unobserved. The barrier
  (`engine/runtime_destruction.py`) checks resources, threads and subscriptions, never `composite_live`/
  `packet_reader_live`. Fix: let the route be a watched Python owner, or close it from the visualizer retirement path
  that runs before the item can be lost.
- **L9. Harness-only use-after-free window in `composite_spectrum_wait_paused`** (`module.cpp`; `spectrum.cpp:595-603`).
  The reader pointer is taken under the lock and then waited on with the GIL released. Another Python thread's
  `unbind`, followed by a sync, would delete it. Only the `pause_in_copy` harness reaches it. Fix: hold a reference
  (as `ReaderEntry` does) for the wait.

## Tests: structure and controls

- No test pins a preset name, a preset value or UI wording. Expectations come from the owning modules (constants from
  the Python modules, block membership from `SPECTRUM_BLOCK`, admission from `render_contract`).
- Every new test file has its control: derivatives (four controls), route (no-route control), backend Studio
  (OpenGL control and widened backends), program (compiled-in pack refuses the new member), packet reader close race
  (idle close), conventions mirror (flip on/off), limited-API, STL and QRhi-include source guards (round 4/5 lines).
- Claims a test does not prove:
  - `test_native_visualizer_route` proves the item's seam, not the route (M4).
  - `test_the_card_maps_the_targets_pixel_...` uses only a window whose logical size times dpr is exact (H1).
  - `test_the_settings_function_gives_the_python_renderers_own_values` covers one configuration (M3).

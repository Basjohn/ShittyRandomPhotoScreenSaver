# System Volume / Mute OSD | Live implementation decomposition

**Status:** queued in `Current_Plan.md` as B0–B3, **not implemented**. This is an independently opt-in ordinary widget, not a replacement for Media's volume control and not a generic always-on overlay. This file owns the actionable decomposition; `Future_Work.md` is a pointer, and `Docs/Guides/10_WIDGET_GUIDELINES.md` owns shared widget rules. Check boxes only against executable evidence, not intentions.

## O0. Existing architecture and feasibility before product code

- [ ] Read and trace `core/media/system_mute.py`, `widgets/system_mute_runtime.py`, `rendering/widget_runtime_services.py`, `rendering/quick/widgets/media.py`, `rendering/quick/display_unit.py`, ordinary descriptor/registry, `rendering/quick/qml/CustomLayoutOverlay.qml`, current `content_extent`, Widget Theme and Settings defaults/retirement. Find current compatible Windows `pycaw`/`comtypes` binding and tests; record owners, import/dormancy and real callback APIs before implementing.
- [ ] **Correct the ownership story:** currently `core/media/system_mute.py` acquires a process-global endpoint at *module import*, while the existing shared system-mute runtime uses a **30-second poll** when its consumer is admitted. An OSD must not claim either is already an external-change callback or that release of a Media lease currently destroys the endpoint. Design a source-owned event subscription shared with present Media consumers. Disabling the never-admitted OSD must not cause an endpoint import, callback, Quick item or timer; if endpoint teardown across admission cycles is required, implement and test it at the existing backend owner and COM apartment, not a second OSD backend.
- [ ] **Event-driven OSD; no recurring state poll.** Core Audio offers `IAudioEndpointVolumeCallback.OnNotify` for volume/mute changes and `IMMNotificationClient.OnDefaultDeviceChanged` for endpoint changes. Use one registered subscription at the shared audio source, not one per widget/display. Verify registration/unregistration and default-device notification using **installed** Windows pycaw/comtypes with fakes first, then a narrow smoke. Keep the COM callback nonblocking: copy only the notification value to a bounded latest-only slot and enqueue at most one GUI wake. Do not query or modify the endpoint, unregister/release COM objects, or synchronously invoke GUI/QML from the callback. Microsoft endpoint/device callback API references and the pycaw volume-callback example establish the available interface; they do not prove our Windows binding/lifetime yet. Do not assume a generic `run_on_ui_thread` is safe on a COM callback thread; prove queued thread-hop and safe apartment ownership, device-replacement release and no callback after retirement. No direct QML/object access, COM endpoint mutation or logging of sensitive COM payload from the callback thread.
- [ ] Decide/record exact candidate display behaviour for multiple monitors: one shared state/callback, explicitly selected display(s) or chosen active output presentation through the existing per-display descriptor. No extra windows, duplicate endpoint acquisition, or per-display callback. Confirm whether a top-level normal widget needs a new lightweight descriptor only, rather than pretending the OSD is a child of Media.

## O1. Source and event lifetime (existing system-audio authority only)

- [ ] Add optional OSD admission to the **same** shared audio source owner, not a parallel system-audio service: one endpoint binding, one callback subscription for the active consumer set, generation-safe detach/rebind. Media's action/readiness and the current 30-second refresh must remain functional during migration. For a callback-proven shared source, **retire the legacy 30-second Media refresh poll** after proving event freshness, in-app control feedback and device-switch recovery; the OSD itself has no polling fallback. During migration keep the existing Media behaviour until the Windows event path is accepted. If notifications cannot be made safe, stop the OSD source gate rather than add another poll. Disabled OSD adds **zero incremental recurring work**; post-lease endpoint and registration retirement needs a dedicated test.
- [ ] Publish one immutable current-volume `[0,1]` + mute + availability + endpoint-generation snapshot. `OnNotify` consumes the notification payload, writes latest state to a bounded shared slot and requests at most one pending GUI wake. GUI consumes most recent value, fences dead endpoint/runtime/widget generations, deduplicates equal effective values, and publishes once to all admitted presenters. High-frequency key-repeat must not queue one signal/timer/renderer update per callback. Avoid re-query races, no SetVolume/SetMute echo on notification.
- [ ] On default output change, detach old notifications and rebind on the owning apartment with generation guards, advertise unavailable on failure without pretending a stale volume is live, retry only by actual device notification or explicitly justified bounded owner policy. If two notification kinds or COM wrappers compete, reconcile them inside the source owner. Stop active callbacks before releasing the endpoint; late callbacks are ignored.
- [ ] Preserve keyboard `End`/`PgUp`/`PgDown` semantics and other Media/Steam/widget work. An OSD notification must be presentation feedback only, never a second control/input owner.

## O2. Dormant retained presentation and Settings contract

- [ ] Choose one stable ordinary widget identifier (proposed `system_audio_osd`), one **canonical** opt-in Settings subtree in `core/settings/default_settings.py` (default `enabled=False`), one descriptor/registration and ordinary family/member activation path. Do not manufacture a second nested `widgets.media.system_audio_osd_enabled` gate if the ordinary member root owns enabled state. Keep settings surface lazy. If a deliberate alias/migration of old keys is needed, prove actual callers first.
- [ ] When enabled and a system-audio event arrives, reveal one retained Quick OSD on the configured display(s). In enabled **global CUSTOM Edit**, expose its shell for move/side X/Y/diagonal/wheel resize even without an audio event; an **off** feature must not materialize an Edit-only exception. Outside Edit, hidden-at-idle rendering is dormant: no continuous frame/opacity animation, no role observers, provider reads or ghost window.
- [ ] Apply existing Widget Theme/surface/border/text/accent/corner/shadow semantics. Reuse Media's **volume-bar visual** only if it can be shared without instantiating Media's runtime/model or coupling its automatic accessory-side layout. OSD fill is left-to-right, with truthful mute/percentage state; support font and size, bar thickness, and text choices `left_of_bar`, `inside_bar`, `right_of_bar`, `none`, `numbers_only`; define readable clipping for compact X/Y and `0%`/`100%`.
- [ ] One event-owned, **restartable** inactivity deadline per active OSD presentation is legitimate: start/restart on effective change, keep fully visible during a burst, then run one bounded fade on idle and stop it at zero. No timer per notification or per-frame polling; cancel/fence timeout/animation on Edit entry, retirement, device change and display-generation replacement. State what hidden/preempted Edit shell does during volume changes.
- [ ] First implementation consumes current ordinary `content_extent` on both axes; shared selected-parent diagonal and square corner/wheel semantics, uniform transform, authored min/floor, Save/Cancel/Undo/Restore/slots and monitor transfer. OSD QML owns only its actual inner bar/text reflow. Define stable semantic roles only for meaningful independently editable singleton chrome; no per-event role array rebuild, no role declared conditionally on text visibility; readiness controls chrome, not identity. Compare retained Edit proxy to actual clipped/mapped paint through live changes. Do not let a text change drive outer parent size.

## O3. Executable gates and bounded operator acceptance

- [ ] Unit/fake COM: disabled-import dormancy; callback registration cardinality; 100+ rapid notifications coalesce to bounded pending wake; ordered latest payload, mute and 0/100; equal-value no-op; no echo writes; GUI-only publication; default-output swap/old-generation fence, missing endpoint, unplug/replug, exception/unregister, repeated enable/disable/reopen and Media+OSD coexistence.
- [ ] Retained Qt: one model/item per admitted display, idle frame-demand quiescence, no QML non-bindable/binding loops or render-when-hidden, coherent volume/mute text/bar, one inactivity timer and fade, Edit shell while enabled and silent, role identity and exact painted clipping under independent X/Y, flip if offered, slots/reopen and teardown, no per-gesture Settings writes.
- [ ] Performance: compare event-loop latency, warnings, updates/frame demand, COM subscriptions, endpoint/Quick counts at idle, one notification and prolonged key-repeat to the accepted baseline. Reject OSD if it adds continuous frame demand or significantly degrades live Edit/Bubble/transition responsiveness. No fabricated 'zero overhead' claim without measuring the admitted and disabled cases separately.
- [ ] Native Windows smoke **only after automated green**: with OSD enabled, change volume externally (hardware/tray), hold keys, mute and switch default output; check one correctly placed OSD, latest value, no mid-hold fade, clean hide, correct repaint after switch. Verify edit shell/Save/reopen on one display; inspect a short bounded warning/latency log if something feels slow. No broad family re-acceptance.
- [ ] After acceptance: update descriptor/default Settings tests, guide/current contracts and a concise operator handoff. Avoid creating another source polling service merely to declare the feature 'implemented'.

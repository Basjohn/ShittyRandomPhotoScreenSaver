# System Volume / Mute OSD | Live implementation decomposition

**Status:** First independently opt-in retained Quick OSD vertical slice is implemented and its cumulative Windows Qt gate passed 78/78. **Real master-volume hardware and CUSTOM physical acceptance remains open**. Media already uses the accepted shared event-driven Core Audio owner. The OSD introduces no endpoint, audio-state poll or per-display callback registration. Do not promote the widget to full acceptance from source/Qt tests alone. This remains an actionable live checklist, not a checkpoint history.

- [x] Trace the Media action and runtime lease path, Qt GUI/COM apartment and real pinned pycaw/comtypes bindings. The source-mailbox, queued Qt bridge and native registration tests passed on the operator's Windows machine (31/31 and 1/1 respectively).
- [x] Implement a single callback source for volume/mute and default-output changes. One pending GUI wake and one latest immutable snapshot coalesce repeated notifications. COM callbacks only copy scalar payloads and queue the retained bridge; all writes/rebinding/unregistration belong to its owning apartment. The device-notification subscription remains active while there is no current speaker, allowing event-based recovery without polling.
- [x] Reconcile the live Media owner in the current *candidate*: `widgets/system_mute_runtime.py` uses per-generation state/consumer leases to `core/media/audio_shared_source.py`, with one callback subscription per active GUI apartment even across overlapping display generations. The retired process-global `core/media/system_mute.py` and 30-second polling chain are not runtime fallbacks. This migration has pure-Python/fake coverage but requires the cumulative Windows test gate before acceptance.
- [ ] Establish **real** external volume/mute notification arrival, output switching, late-callback fencing and teardown in a bounded Windows scenario. The accepted read-only registration test did not trigger a real hardware event. Do not automatically alter user volume or device just to make a test green; the minimum manual smoke may be needed once, after the automated gate.
- [x] Choose one configured display policy for the OSD within the existing per-display ordinary descriptor, without adding windows or per-display callback registrations. Keep OSD presentation optional independently of Media.

## O1. Consume the existing audio authority, never fork it

- [x] Add an OSD lease to the accepted shared system-audio source; the OSD is a presentation subscriber, not an endpoint or playback/control owner. No OSD source poll, audio worker, second COM apartment, per-display registration, second slider-action path or duplicate model authority.
- [x] Publish one coherent volume `[0,1]`, mute, availability, endpoint-token and revision snapshot to the admitted presenters. Initial unavailable state, device handover, no-speaker rebind and callback echoes must preserve truthful display and not create an unbounded GUI queue.
- [ ] **Prove in native Qt** disabled OSD adds no runtime endpoint/Qt item/timer/animation work. When Media and OSD are both inactive, the final source lease unregisters and retires the endpoint on its owning apartment.
- [ ] Preserve existing keyboard End/PgUp/PgDown global-volume controls and Media mute feedback. The OSD reacts to notifications and does not reapply their values as commands.

# Steam Games You Follow | Live feasibility-to-release decomposition

**Status:** queued under `Current_Plan.md` C0–C3; **G0 not proved, product not implemented**. Product label **Games You Follow**, existing compatibility identity `steam_progress`, existing `--devsteam` gate for the unfinished replacement only. This replaces the unfinished Steam Progress/Journey scaffold's product meaning; it is not an owned/recent/wishlist feed, personalised Steam-wide ranking or Store scraper. Tick each phase only with its evidence; no checkpoint diary belongs here.

## G0. Source/security admission | mandatory before product service or GUI

- [ ] Trace the current credential/private Steam source path (`core/steam/backend.py`, request policy, profile state, cache, assets, action router) and current `steam_progress` settings/caller/descriptor scaffold; capture actual request wrapper and version before adding a source. Pin pre-feature revision/GODZIP for rollback without copying old scaffold visual code into the new card.
- [ ] **Existing-key proof:** fixture + narrow authorized live probe of `IStoreService/GetGamesFollowed/v1` with the **existing user's Web API key + linked SteamID64** through the current backend. Confirm response shape, request form, empty/private/denied states and key requirement. The endpoint metadata indicates a key-gated route, but has **not proved the user's current credential class works**. If it does not, stop at G0 and leave `--devsteam`/`steam_progress` dev-gated: no QR/Steam Guard, cookie, login/session, scrape, owned/recent/wishlist inference or substitute source.
- [ ] Fixture-prove bounded `ISteamNews/GetNewsForApp/v2` public app-specific `APP_NEWS` for accepted follows only: ID/date/title/feed/tags/source URL, empty/invalid/private/401/403/429 and response bytes/time. **Exclude** publisher-only `GetNewsForAppAuthed`, article scraping and arbitrary whole-library news scanning. Choose an explicit follow-set max, app-query fan-out/request budget and accepted visible candidate count from measurements; fail safely if unbounded.
- [ ] Independently validate source-article **HTTPS and redirect** policy with the existing secure-helper/action route, and news-image reference host/scheme/byte/signature policy with the existing asset cache. Image host allowlisting is not proof of article-navigation safety. Until validated, headline action disabled and app-art fallback used; no raw arbitrary URL emitted to QML, helper rejection fails closed.
- [ ] Confirm credentials/SteamID remain in the existing private source/account store, never Settings, QML roles, logs, cache filenames, exported SSTs or test fixtures. Use only redacted deterministic fixtures in automated suite. Record G0 success/failure and exact evidence; neither a speculative source nor a GUI mock may be marked released.

## G1. Neutral source/cache and bounded runtime | only after G0

- [ ] Define one source/provenance contract: authoritative followed set, accepted news per admitted app, source timestamp/quality, `available`, `empty_follow_list`, `private`, `unavailable`, `no_usable_news`, `stale_cache`. No false empty state on source failure. Source ownership is explicit follows only, never candidate activity or Steam ownership.
- [ ] Reuse `SteamRequestCoordinator`, backend status/redaction, locks/backoff, atomic `SteamCacheRecord` envelope and opaque account-private profile cache. Keep **last-good followed set and last-good admitted news indefinitely** after freshness window on failure, marked cached/stale; failures/invalid responses never freshen or delete it. Reset/identity change/schema corruption are explicit deletion boundaries. No separate per-display cache or request scheduler.
- [ ] Normalize minimal bounded story fields: AppID and stable news identity private to runtime; title/headline/published/feed/tags; one policy-approved article target and image reference, if any. Deterministic dedupe/ranking (one or more items per app only if product choice explicit; newest timestamps then stable IDs), hard cap before enrichment. Avoid a long-lived read-history/dismissal DB and avoid raw payload caching.
- [ ] News item image first only if G0-proven, else existing `core/steam/assets.py` shape-matched art (`wide` default, `square`, `portrait`), at most one proven alternate shape on definitive missing/invalid. Local-file-only artwork role, bounded byte/image validation, retained `ArtworkFadeImage` behavior, selected visible row-only hydration and revision/app/item/shape/source/generation fencing. Never fetch article pages to hunt media.
- [ ] One runtime-generation shared owner plus per-display leases under existing Steam family/member/developer/real-consumer gates. Existing canonical `widgets.steam.refresh_minutes` owns periodic cadence. Manual refresh uses same coordinator. Unchanged accepted snapshot is a no-op for model rows/artwork/rendering; Settings opening starts no backend. Last lease stops feature-only refresh/assets, fences late work and preserves other Steam cards' legitimate shared owners.
- [ ] Stable presentation-safe Python models/list IDs and coherent immutable accepted revision; QML sees display text, local-file artwork, source/cache labels and action availability, not private AppIDs, account tokens, raw article/image URLs, provider objects or a business/persistence API.

## G2. Current retained Qt Quick widget and CUSTOM geometry | first GUI slice

- [ ] Reuse the **existing** ordinary descriptor/registry/host and one retained `GamesYouFollowPresentation.qml`; no extra QWidget/QQuickWidget/window/provider timer or custom geometry owner. Stable identity remains `steam_progress` until a real persisted-schema/slot migration is explicitly proven and admitted. Expose two authored product variants `single_row` (one story) and `double_row` (two stories), not a row count inferred from current news volume. Overflow is truthful bounded summary, not silent source truncation.
- [ ] Reuse the family Steam header, shared theme roles and shared `ArtworkFadeImage`. Present game/title context, headline, honest source/time labels, safe news-image-first/app-art fallback; shape controls `wide`/`square`/`portrait`. Typography settings include font family/size, alignment `left`/`center`/`right` and bounded `headline_truncation_chars` followed by measured QML line clamp/elision; optional event-owned tooltip only when truly elided, no marquee/carousel/polling.
- [ ] Admit **three meaningful singleton semantic child roles** where visible/available: `header`, `refresh`, `overflow_summary`. Declare them stably independent of provider/visibility/live normalization; readiness may hide chrome without retiring an active delegate. Resolve alternate painted targets inside the selected Edit mapper, observe applied QML transform properties rather than a non-bindable `QQuickItem.transform` list, compare actual painted/clipped target to proxy. If `overflow_summary` is conditionally presented, its **role identity remains declared**, even when not painted. Do not add per-story draggable siblings or per-row child persistence.
- [ ] Repeated stories remain one family-authored X/Y row/column layout with stable semantic row IDs. If the operator requests reorderable columns, **reuse the accepted Reddit/Gmail widget-wide semantic column-rail contract** with a stable one-per-column order in the existing CUSTOM transaction; do not duplicate per-row handles, reorder provider data or implement a second ordering authority. Do not assume that column swapping is a v1 requirement without approval.
- [ ] Declare truthful preferred outer sizes for both variants and **both** independent shared `content_extent` axes from first implementation. Side X/Y changes allocate row artwork/text and vertical space without changing story count/variant or app news selection; selected-parent diagonal changes both, square corners/wheel uniformly scale the complete reflowed card. Shared session owns Save/Cancel/Undo/slots/Restore/position/monitor and floor admission. Edited child X and Y are separate live authored-rail deltas; ordinary layout/flip remains family-owned. Child moves cannot grow parent or publish child-required extent, collisions OFF still respects real containing surface. No family-local Settings geometry writes, QML resize timer, parent-size feedback or extra normalization authority.
- [ ] Header may flip **placement only**, never bitmap/text pixels; test source/game/title/AGO/source lanes at compact independent X/Y after prior child edits, reset, save/reopen, multi-display generation. Variant and Settings preferences are configuration-owned, CUSTOM geometry is session-owned; layout-slot transaction restores visible row variant along with ordinary ON/OFF and CUSTOM geometry without smuggling source/account/cache state.
- [ ] Store artwork and headline emit narrow semantic action plus stable selected row handle; Python revalidates private current AppID/approved URL on click and routes via existing Store/secure-helper policy. A helper rejection must not open a raw URL or terminate the screensaver. No QML raw URL navigation.

## G3. Canonical Settings and lifecycle

- [ ] Keep exactly one `widgets.steam_progress` canonical defaults/settings/persistence root for v1, with Games You Follow labels; retain caller-proven existing position/font/card-style fields, introduce only enabled, `single_row`/`double_row`, alignment, artwork shape, truncation and justified visible chrome choices. Existing Steam credentials, privacy and refresh remain in their current owners. No second `widgets.games_you_follow` schema, shadow defaults JSON or state copied into CUSTOM.
- [ ] Update settings buckets/registry/predictor/preview and canonical defaults/constraints/migration/SST/slot tests in the same slice; lazy Settings load never imports/starts a provider. Do not flatten authored presets or use the unfinished Steam Progress mock visuals as a parity target.
- [ ] True dormancy when any gate fails: Steam family activation, member ordinary enabled, `--devsteam`, authorized source configuration and real presentation consumer. Last-display retirement, app disable, account change and generation replacement fence requests/image callbacks and release retained model/item without shutting down Steam siblings.

## G4. Acceptance matrix and exit

- [ ] **Source/privacy tests:** key-path fixtures and live-gate evidence, finite follow/news budget, malformed/429/private/stale/empty statuses, secure-helper redirect policy, news-image byte/signature rejection, no leaked ID/key/URL into Settings/QML/logs/export, wrong-source substitution forbidden.
- [ ] **Owner/cache tests:** one coordinator/cache/runtime across displays, last-good indefinitely readable, no freshness reset on failed response, stable list ID/no-op, selected-row-only image work, stale completion drop and zero work with no consumer.
- [ ] **Qt geometry/lifetime tests:** `single_row` and `double_row`, compact/large independent X/Y, both artwork shapes/crop states as configured, text elision and overflow, semantic flip if offered, proxy exact painted identity/bounds/clipping and 20+ normalization/content updates with same delegate; hide/reveal, Save/Cancel/Undo/Restore/slots/reopen, off-Edit zero observers, no QML transform-list warnings or live-parent feedback. Authored siblings stay in normal row rails when one singleton role is edited.
- [ ] **Performance tests:** baseline/candidate event-loop latency and retained objects, no repeated network/image/model/layout work per pointer event, no re-schedule on identical source data, correct Steam-sibling cost and retirement; don't infer performance from FPS only.
- [ ] **Physical smoke only after tests:** one cached and one fresh authorized snapshot, independent X/Y resizing of each variant, correct artwork/news/article action and one disable/re-enable/Save/reopen; record exactly what automated tests could not prove. A source that failed G0 has no physical product test.
- [ ] Mark implementation accepted in `Current_Plan.md` only with explicit Windows source, Qt/security, lifecycle and performance evidence; remove completed tasks from live queue rather than append checkpoint history.

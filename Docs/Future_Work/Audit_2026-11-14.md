## Verdict on the merged work

- **N2.3 (8dff805e).** The seqlock is correct on x86-64. The writer (`packet_abi.py:231-238`) stores
  `sequence_begin` odd, the head, the payload, `sequence_begin` even, `sequence_end`, then `latest_sequence`. The reader
  (`packet_reader.cpp:407-434`, `:595-657`) loads `latest`, finds the one slot whose begin equals it, loads
  `sequence_end`, copies the head, then (after the payload copy) loads `sequence_begin` again. Each load is a
  `__iso_volatile_load64` followed by `_ReadWriteBarrier`, so the compiler cannot move the copies across them, and x86
  never reorders a load with an earlier load: if any copied byte came from a newer write, that write's earlier
  odd-begin store is visible to the final begin load, which then differs. All u64 words are 8-aligned (64 + k x 16).
  D1: the reader maps its own view by name and closes the handle at once; every read and head read pins it and the
  last pin unmaps it, so a `release()` racing a GUI `readHead()` unmaps on whichever side finishes last. D2: only
  `read()` writes `consumed_sequence`, at the accept edge; `readHead()` changes nothing outside the control. The head
  admission is `admit_slot_head(accept="native")` check for check, in the same order. The generated header equals
  `render()` and `--check` passes, its negative control sees a changed mode table or rule order, and the `SlotHead`
  `static_assert`s tie the struct to the generated offsets. Every negative control in `tools/packet_reader_adversary.py`
  bites, by reading each case against `read()`. `skip_seqlock` fails the odd latest and the end-behind cases.
  `head_resets_watermark` fails the duplicate. `accept_unordered` fails the stale case. `skip_head_check` fails every
  head or record refusal, because the slot is then accepted (and the oversize case is torn by the capacity guard).
  `acknowledge_refused` fails every refusal through `consumed`, which `_refusal_checks` reads after the read: the
  argument is evaluated first. `skip_identity` fails the foreign case. The GitHub run recorded every control failing
  (N23 VERDICT PASS).
  The `PacketMailbox.publish` change (count a superseded frame only after its successor is in the slot) is correct.
- **N2.7's leftovers (41671a42).** The reveal rule is one function (`display_manager.py:5272-5301`). On OpenGL it is
  unchanged: `_on_image_displayed` adds the screen to the authoritative set before it asks, so the new check equals
  the old one there. `frame_presented` is published once per scene and only on a backend without background renderers
  (`scene_controller.py:3635`); OpenGL pays one attribute test per swap. Terminal barrier: no exit path can now hang.
  A terminal barrier keeps its 8 s timeout (`runtime_destruction.py:29`), and on timeout it still runs the
  finalization (`:606-614`). It is armed only when the event loop is live (`engine_lifecycle.py:149-157`). The only
  stops whose barrier changed are `cli_exit_after` (`main.py:246`) and `no_display_shown`
  (`screensaver_engine.py:1291`), and both run inside the loop. The shader packs are rebaked from discovered sources
  with a freshness check. The greyed modes are correct on the Visualizers page; one route outside it is not (fix
  soon 2).
- **1D.7 (9a6181e5).** The card's Rotate outside Edit runs Edit's own turn on a direct session and commits through its
  end (`display_manager.py:1540-1567`). The expanded card opens Fullscreen Edit, turns, and Saves or cancels in one call
  (`:2747-2768`). An activation in progress refuses before anything opens. `present_custom_layout_draft` runs one route
  reapply at the Save edge (`quick_display_visualizer_owner.py:1380-1389`), never per frame. Restore Size and Child Lock
  still go through `_route_hover_edit_action`, pinned by `test_restore_size_and_child_lock_still_enter_edit`. Only the
  Visualizer is content-rotation capable (`visualizer_mode_registry.py`), so routing every Rotate outside Edit through
  the Visualizer path loses nothing.
- **R-205, R-206 (a5e6b501).** The trails' sampler table is `EB_SAMPLERS` (the background at unit 5), checked on the
  GPU for every pass-block program that declares `uBackground`. The fractional wake end is consistent end to end. The
  record's `count` is `1 + tail`, or `1 + lead x tail` when even the newest point has aged. The shader's `trailReach` is
  `lead + count - 1`, which puts the end exactly where the water reaches `HISTORY_SECONDS`, and `ceil(count)` never
  exceeds the points kept (`young + 1`).
- **R-208 (939647b0).** No lambda or partial is connected in `ui/styled_popup.py` any more; `sender()` carries the
  value. The Neon test now builds its unit before stubbing the registry.
- **The lead's commits.** `mode_runs` reaches every Toggle state and every Choice offer: variant `a`'s and `b`'s
  offers are assumed, but the test checks them against the spec, so a variant that changed its offers fails it. There
  are 129 runs over 9 modes. 5a8ca60a is order-dependent (fix soon 1, fixed).

No environment-variable flag, no new timer or polling, no preset named or counted, nothing per frame at rest, and the

## Fix soon

1. **Fixed (ef684a6e).** `test_spinbox_stylesheet_attached` (5a8ca60a) is red whenever a test that builds a
   `SettingsDialog` runs before it in one process. It imported `SPINBOX_STYLE` at module import, and a theme install
   rebinds `shared_styles.SPINBOX_STYLE` (`ui/tabs/shared_styles.py:1812-1820`). Scenario: any chunked or combined run
   with such a test first. Proof: `pytest tests/test_visualizers_tab_backend_modes.py tests/test_widgets_tab_current.py
   -k "spinbox_stylesheet_attached or backend"` gave 1 failed, 2 passed (alone, the test passes). After the fix (the
   module attribute is read at assert time) the two whole files give 53 passed; the failing pair above is the negative
   control. The same theme-state leak is the plan's open "Isolate active Widget Theme state" box (section 3).
2. **On Vulkan, a Studio's mode switcher offers greyed modes, and choosing one raises.** `ui/studio/settings_link.py:620-624`
   `modes()` lists every enabled Studio mode, while `switcher` calls `tab._select_mode_page(target)`, which raises
   `ValueError` for a mode without a renderer (`ui/tabs/visualizers_tab.py:442-443`, 41671a42). Scenario: once N2.5
   ports Spectrum, the lead's Vulkan rehearsal opens Spectrum's Studio (`has_studio` is True for it) and picks another
   mode in its switcher. The exception escapes a Qt slot, and the Studio stays on Spectrum with a traceback in the log.
   Proof: by reading. `has_studio` (`ui/studio/registry.py:58-63`) filters by backend, but `modes()` does not use it.
   Not reachable before N2.5, since no mode has a Vulkan renderer. Fix with N2.5: filter `modes()` by `has_studio`,
   with a test on the real dialog under `_on_backend` (as `tests/test_visualizers_tab_backend_modes.py` patches it).
3. **For N2.5: the reader's lifetime against a render-thread read.** `PacketReader::~PacketReader`
   (`packet_reader.cpp:239-247`) unmaps unconditionally. `packet_reader_close` (`module.cpp:903-917`) retires,
   releases and deletes on the calling thread. `stateJson()` reads plain counters and `QString`s. All of this is safe
   today only because every entry holds the GIL. Scenario: in N2.5 the render thread calls `read()` from C++ while the
   GUI closes the reader, which is a use after free and an unmap under a copy. Proof: by reading. Today's harnesses call
   every entry from one Python thread. The N2.3 leftover box ("close during copy" hook) should name the reader object's
   own lifetime, not only the view's: deletion only after the render-thread retire job.

## Low

1. `packet_reader.cpp:19-21` guards on `_M_X64` alone, which MSVC also defines for ARM64EC, a weakly ordered target
   where the compiler-barrier seqlock is not enough. Add `|| defined(_M_ARM64EC)` to the `#error`. Not reachable while
   the workflow builds x64 only.
2. `applyDrop` (`packet_reader.cpp:395-405`) sets `m_droppedThrough` to at most `m_accepted`, so the watermark in
   `read()` (`:596`) is always `m_accepted`. The drop's own watermark is redundant: no control can show it working
   (`head_resets_watermark` resets both). This is harmless, but D2's text credits `dropped_through` for what `accepted`
   does.
3. `skip_seqlock` turns off three guards at once: the odd latest, the end check, and the begin re-read after the copy
   (`packet_reader.cpp:610-614`, `:426-432`, `:654`). No control isolates the post-copy re-read, the guard the race
   depends on. The held stress run still covers it positively (0 mixed records).
4. `packet_reader_check.py:225-227` ("retiring: no copy starts") has no negative control.
5. A second exiting stop while a terminal barrier drains cancels it (`engine_lifecycle.py:577-586`). With
   `display_manager` already `None` (`:291`), the second stop then finalizes and quits at once, before the Quick windows
   retire. Scenario: `--exit-after` firing within the drain of a user's exit. This is the same class as the open N2.7
   leftover "exits that bypass the stop"; add it to that box's route list.
6. A slot of another identity whose schema the reader does not admit is refused, which fails the stream, rather than
   counted as foreign: admission runs before the identity check (`packet_reader.cpp:627-641`). This is parity with the
   Python reference. The order is a decision for the lead (below).

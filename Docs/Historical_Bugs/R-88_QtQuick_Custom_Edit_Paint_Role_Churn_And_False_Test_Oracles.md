# R-88 | Qt Quick CUSTOM Edit paint, semantic-role lifetime and churn

**Incident window:** 2026-09-18 to 2026-09-20. **Status:** shared geometry/role-lifetime and grouped System Stats physical/Windows checks accepted; retained child-guide native test accepted (25 passed). Wider project/outer-guide churn is **not** claimed solved. This is a historical failure record, not an active plan or a mandate to reimplement every mitigation.

## Observed failures

The CUSTOM child editor had several interacting failure classes after Qt Quick migration: child edits could detach from authored X/Y reflow or flip back on live wheel resize; saved/reopened or third-display-generation roles could lose the painted target; Weather's inherited Scale/Translate changed the actual visible location while its selected Edit proxy retained an older rectangle; Achievement Pulse's visibility-dependent role list retired its artwork delegate when presentation state changed. A temporary shared-mapper correction produced extremely slow Pulse/Weather dragging and tens of thousands of QML warnings during a short run. Clock digital content overpainted its compact allotted rectangle; a changing Clock role-array dimension could retire and replace the selected delegate. System Stats exposed overlapping per-metric handles that often moved no meaningful whole-unit content. Child snap-guide Repeaters could recreate guide items even when the published snap had not changed.

The errors were not one generic 'bad QML' bug. Paint alignment, role identity, true authored layout, clip/containment, and unnecessary scene mutations each had separate owners and acceptance evidence.

## Root causes and false fixes to avoid

- Reading `QQuickItem::transform` while evaluating a live QML mapping binding enumerated a **non-bindable list** and generated repeated warnings and main-thread diagnostic work. Removing that read was necessary, but observing only a model/source input was insufficient: `mapToItem()` could evaluate **before** QML applied a bound Translate, leaving an old X position. Selected-only mapping must observe the **applied** named `Scale`/`Translate` property on the relevant retained ancestor, then map actual four corners and intersect ancestor clip regions.
- Placing live preferred/normalization values or transient visibility in `customEditableChildRoles` forced a new array and Repeater delegate retirement during resize/content changes. Role existence must be stable; actual target/readiness/normalization are observed only in the selected retained Edit delegate. The renderer may have a transparent semantic carrier whose own opacity is not the visibility of the painted descendants.
- Geometry tests initially compared the mapper's **clipped** painted footprint with an **unclipped** oracle (37.2 vs 136.4 px in one transform case). A separate test attempted to marshal `QQuickTranslate*` through unsupported PySide6 `QObject.property` conversion, and another misread an evaluated QML expression's `(result, isUndefined)` tuple. A 0.375-pixel non-painted Clock Column overshoot was tested against the strict painted-target 0.02-pixel tolerance. Tests must prove painted target and role identity using supported Qt probes, track clipping state and separate harmless non-painted fractional layout from actual ink escaping the card.
- A Clock test observed a stale, parentless QQuickItem because the role array rebuilt while the host was changing intrinsic geometry. Other tests dereferenced a QQuickItem **after** host retirement or asserted that dense Steam cards still expose the deliberately retired child-driven outer-size requirement. Never patch production to satisfy a stale test fixture; test the current parent-owned extent and actual retained scene instead.
- System Stats' per-accent/per-label/per-value handles were semantically misleading because its user-editable unit is the **whole metric stack**, alongside the header and top separator. A first-visible representative cannot serve as the proxy for an entire enabled-card group. The family QML owns internal panels and flip; the CUSTOM owner edits exactly three meaningful targets, one group target enclosing every enabled painted card.
- Array-backed child-guide Repeaters created presentation items on repeated snap publication. Retaining one guide item per axis with bindable position/kind/visibility avoids that Edit-only allocation path. **This does not prove the independent outer peer/centre guide system thrashes**; audit it by observing actual changes before altering its multi-line model.

## Corrections and evidence

The shared selected Edit mapper observes inherited ordinary item geometry/clip and **explicit applied transform dependencies** without reactive transform-list reads. Family QML retains authored row/column reflow and compact paint containment; CUSTOM owns interaction, uniform scale, content extent, Save/Cancel/Undo/slots and persisted child deltas. Steam/Weather/Media/Clock/Reddit/Gmail role declarations became stable across normalization and visibility. Media's volume accessory keeps its own live normalization/automatic side placement. Clock's digital compact fit preserves its natural authored layout and analogue centered face. Reddit/Gmail use one widget-wide semantic column permutation for repeated rows rather than per-row free placement. System Stats uses its accepted three-role design; moving a child does **not** grow outer parent extent. One retained child snap guide per axis replaced array-backed one-guide Repeaters.

The operator physically accepted Pulse/Weather responsive drag and correct rectangles; Clock digital compact layout; Reddit/Gmail rails; System Stats' three meaningful roles. The cross-family Windows gate passed **85 in 7.60 s**. The later child-guide-focused Windows gate passed **25 in 2.12 s**. These are acceptance for those tested contracts, **not** a measured claim that every unrelated churn source or the entire repository has been audited/performance proven. A new OSD or Steam card inherits these contracts but must prove its own retained QML lifecycle and runtime cost.

## Durable regression guardrails

1. Keep stable semantic role IDs/arrays, declare independent of provider content and live dimensions; readiness is a separate selected-only fact. Compare actual retained target identity and mapped **clipped** painted bounds, not role name or source-code substrings alone.
2. Do not reintroduce QML non-bindable-list binding, source-input-only transform invalidation, GUI-thread scene scans, off-Edit role observers, per-frame geometry or per-pointer Settings writes. Test both direct applied-transform and source-driven updates with legitimate Qt APIs.
3. Only the outer handles may change a parent's CUSTOM size/extent; edited child X and Y remain independent deltas from the **live** authored rails, including semantic flip. Collision OFF does not disable outer containment. Stable Save/reopen/third-generation, Undo and teardown are required.
4. Keep tests tied to current authority: one selected target may be intentionally unavailable, QQuickItem pointers die with their host, clip is part of painted footprint, and the System Stats group is the union of enabled panels. Test automatic Media volume relocation rather than assume a fixed side.
5. Measure warnings and event-loop/scene-publication cost in active Edit and ordinary runtime separately. The correct repair reduces **redundant** work without throttling effective movement or weakening rendering freshness/Bubble reactivity. A native Qt green test is not by itself a universal performance benchmark.

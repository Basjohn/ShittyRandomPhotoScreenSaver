# Light-theme legibility: bounded native verification

The shared semantic classifier drives reversible light-palette typography and the explicit global soft-text-shadow
modifier. Theme file schemas remain Settings v6 / Widget v3; no authored palette or card background changed.
`Docs/Contracts.md` → Shadow authority owns the enduring rendering contract.

- Settings uses real intermediate variable weights through a private Jost family, with original static dark matching.
  Root/shared/lazy style edges and tooltips use the same projection; repeated application and dark glyph round trips pass.
- QLabel shadow geometry uses the already padded content rect, margin and indent once. Direction arrows and combo
  indicators consume existing semantic roles. Native Glass/Acrylic controls, labels, headings and tooltips were inspected.
- Runtime shadow glyphs remain admitted. The light-only modifier diffuses their silhouette, preserving authored signed
  offsets and alpha; crisp foregrounds, dark shadows, card surfaces and Settings theme `ShadowStyle` values remain intact.
  Header logos soften their existing effect. All ordinary family styles/models forward the same global style bit.

Native receipts under `tmp/light_theme_audit/` cover `accepted_soft_pearl`, `accepted_soft_chrome`,
`accepted_dark_instrumented` and `accepted_soft_settings`. Light runtime cards were composited over black/white,
including a 65% authored surface, Clock labels, Media text/header logo and Context Menu. Settings checkbox click/save/
reopen preserved every other global control. `final_pearl_eb_quality/default.png` confirms only the mode's own Detail row.

The final shadow-only half-resolution capture measured +7.88 MiB dedicated GPU memory and +0.057 ms mean render CPU
in this bounded scene; 60 Hz cadence was unchanged. The operator explicitly accepted that cost. These observations
are not a universal GPU budget or performance-neutrality claim. Full-resolution capture cost more and was not retained.

Focused gates included 131 retained runtime checks and 85 UI/descriptor checks, plus actual font-ink, dark-font round-trip,
QtWidgets import-purity, signed-offset/source-edge and global-control preservation checks. Whole-desktop pixel identity
is not asserted: compositor/background changes invalidate it even when dark component styles and glyphs are identical.

One final dark probe timed out before capture; no pixels from it count as validation. The single instrumented retry
completed all stages and legal retirement; the earlier startup stall did not reproduce and has no established cause.
All owned windows/processes were confirmed absent. Probe wrappers now reuse the existing process-tree Job Object owner,
so a Windows venv redirector and its actual interpreter share the external deadline.

## Settings bucket persistence | source audit of a deeper functional mismatch

**Operator intent:** remembering expansion exists solely to let an editor leave/reopen Settings and return to the **same active pill (or top-level tab without pills)** and appropriate open editing section. At all other contexts the default is closed. Merely enforcing one open bucket *per page* is insufficient. A nested active ancestry may need to appear open to reveal the remembered leaf; its ancestors must not become unrelated independently remembered buckets. Preset edits/Custom behavior must remain unchanged.

**Confirmed source contract discrepancy, not a native visual claim:**

1. [`core/settings/ui_bucket_state.py`](../../core/settings/ui_bucket_state.py) chooses one winner *per scope*, and `widget_bucket_scope()` deliberately allocates each Widget pill a distinct scope and Steam card sub-buckets another. Stored state can have multiple simultaneous true keys from different inactive pills.
2. [`ui/tabs/widgets_tab.py`](../../ui/tabs/widgets_tab.py) `_on_subtab_changed` changes visible section and scroll but does **not** clear the former pill's remembered expansion; setters write all true keys from all scopes. Lazy sections are constructed from that same persisted state. `restore_view_state` restores selected section but doesn't prune dormant states.
3. [`ui/tabs/visualizer_settings_context.py`](../../ui/tabs/visualizer_settings_context.py) `visualizer_bucket_scope` keys by **mode**, letting more than one mode remember an open leaf. It reconciles Custom and Technical leaves *within each mode*, while `visualizer_adv_states` and `visualizer_tech_states` are independently persisted maps of outer disclosures. [`ui/tabs/visualizers_tab.py`](../../ui/tabs/visualizers_tab.py) `_select_mode_page` swaps hydrated bodies without closing dormant mode disclosures.
4. [`tests/test_widgets_tab_current.py`](../../tests/test_widgets_tab_current.py) `test_widget_bucket_state_roundtrip` explicitly expects Clock/Layout, Media/Controls and Reddit/Secondary all open after reopen. [`tests/test_settings_bucket_single_open_contract.py`](../../tests/test_settings_bucket_single_open_contract.py) checks multiple Widget scopes and multiple Visualizer modes simultaneously retaining opens. These are **wrong or at least incomplete tests for the newly clarified UX contract**; do not make them pass by continuing the old behavior.
5. [`ui/settings_dialog.py`](../../ui/settings_dialog.py) stores per-tab view states separately. Tab/pill identity, lazy page hydration, selected preset and expanded ancestor path must be considered together; closing only visible widgets can leave stale persisted values or resurrect them on rebuild.

**Required acceptance sequence (all open):** fresh Settings → all closed; expand nested Steam child → visible parent/ancestors support correct path; switch to unrelated pill and back → no dormant expansions; switch to other Visualizer mode and back → only current context remembered, not multiple modes; close/reopen Settings from EB after changing a colour → restore EB as active context with just its relevant editing bucket/path; switch between top-level tabs with and without pills; save/edit preset and reopen; disable/re-enable family (lazy retire/rebuild); use a conditional bucket and Deep/Surface mode switch; check nested siblings and any parent rails remain geometrically correct; restart Settings process; verify legacy multi-open profile normalization is deterministic without startup writes or clobbering user presets. Revisit persistence naming/resolution as necessary rather than adding timers, polling or a second state store. **Native QWidget visual, event and lazy-lifecycle validation is mandatory**, absent from this container.

**Do not silently implement a guessed policy for already hidden pills.** The explicit current-context contract above is authoritative; a local agent should test navigation transitions before changing persistence. Existing tests that assume multiple inactive open states must be updated as behavior tests with the desired single active context, not discarded wholesale.

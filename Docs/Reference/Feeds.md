# Feeds | Durable architecture contract

This is the current architectural contract for the shared Feed foundation. Product/runtime surfaces not yet implemented remain in `Docs/Future_Work/Feeds.md` and must not be inferred as already shipped.

## Identity and authority

FEEDS is one bounded widget family. Four CUSTOM slots have stable IDs (`feeds_custom_1` through `feeds_custom_4`) and canonical dormant defaults; all four are admitted to runtime through the same adapter, descriptor, presentation and Settings builder, and an unconfigured or disabled slot costs nothing. A configured name such as `Nyaa` is presentation only and never becomes a settings key, cache identity or runtime registry identity. Future NEWS widgets/providers follow the same rule: stable category/provider IDs are independent of the current endpoint URL.

`core.settings.default_settings.DEFAULT_SETTINGS` remains the product-default authority. `CustomFeedConfig` repairs missing/malformed headless values from that canonical root rather than embedding a parallel authored-default table. User-authored CUSTOM `feed_url` and `name` are preserved by global Reset; ordinary display/theme tuning remains resettable.

## Layer boundaries

`core/feeds/transport.py` owns one bounded HTTP transaction. `core/feeds/discovery.py` owns resolving a website address to its verified feed. `core/feeds/parser.py` owns RSS/Atom bytes-to-model normalization. `core/feeds/cache.py` owns the durable versioned last-good record. `core/feeds/source.py` owns one cache-first refresh transaction and persisted backoff decision. `core/feeds/projection.py` owns pure snapshot-to-presentation policy. `core/feeds/probe.py` is the one explicit viability seam used by Settings TEST FEED and the operator probation tool. None of those core layers owns Qt objects, QML, periodic timers or Settings UI.

`widgets/feed_runtime.py` owns generation-scoped scheduling/source leases. `rendering/quick/widgets/feeds.py` owns retained presentation projection/action admission; `FeedPresentation.qml` is presentation only. Its `ShadowedText` instances use the component's supported `wrap` boolean instead of the native `Text.wrapMode` property; a native `QQmlComponent` compile gate is mandatory for any QML property changes because an invalid custom property can prevent the *entire screensaver engine* from initializing. The package root intentionally has no eager parser/network imports. Importing Feed configuration/source in a clean interpreter does not import `requests` or `feedparser`. Cache-only `FeedSource` admission also keeps parser and HTTP transport construction lazy, so a fresh last-good snapshot can paint without creating a network session.

## Transport

- HTTP/S only for feed documents; malformed/non-network endpoints are rejected before I/O.
- Explicit connect/read timeouts, redirect ceiling and decompressed response byte ceiling.
- Bounded name resolution (`core/network/bounded_dns.py`, shared by every IO-lane network family; Contracts § Network transports): `socket.getaddrinfo` ignores socket timeouts and cannot be interrupted, so each hop's host (or the proxy's, when one applies) is resolved on a short-lived daemon thread with a 4 s deadline and cancellation checks before `requests` connects; the connection then reuses the operating system's cached answer. Redirects are followed by the transport one bounded hop at a time (HTTP/S targets only, five hops). At most eight lookups may be in progress; beyond that a lookup fails at once as an offline-class failure. The artwork transport resolves through the same bound. Before this, one stalled lookup pinned a worker of the four-worker IO lane shared with Media, Weather, Reddit, Gmail and Steam, blocked the engine's exit wait for its full 5 s, and kept the process alive afterwards because the interpreter joins thread-pool workers (measured 12.2 s for a 12 s stall). A DNS failure has no HTTP status, so it never starts feed discovery.
- Streaming cancellation checks allow later runtime retirement to stop bounded work.
- Conditional `If-None-Match` / `If-Modified-Since` is sent only when the cached endpoint fingerprint still matches the current endpoint.
- Final redirect URL is retained and becomes the base for relative item/home/media/enclosure URLs.
- Feed query strings/fragments may contain private tokens. Runtime/tool logging uses redacted scheme/host/path form.
- `feedparser` receives bytes; it is never allowed to perform production network I/O itself.

## Feed discovery

A CUSTOM address may be a feed or a website (`https://arstechnica.com`, or a bare `arstechnica.com`, which means HTTPS; `feed:` and protocol-relative forms are accepted, nothing else widens the HTTP/S rule). There is **no per-site knowledge**: every candidate comes from a published convention and is accepted only after the production transport/parser fetches it and finds a feed with items. In order:

1. the address itself, when it already serves a feed (any supported format; a feed served with a wrong `text/html` type is still sniffed as a feed), or when it is an IndieWeb h-feed page that declares no other feed;
2. feeds the page advertises: the RFC 8288 `Link` header, then HTML `<link rel="alternate">` of an RSS/Atom/RDF, JSON Feed (`application/feed+json`, or `application/json` titled as a feed), JF2 or h-feed (`text/mf2+html`) type, honouring `<base href>`. A feed under a section page's own path wins (`/notes` → `/notes/rss`, a WordPress category page → its category feed); otherwise document order; comment feeds last. oEmbed and API JSON alternates are ignored;
3. feed-shaped `<a href>` links on that page. A link back to the page's own path (language, sort or page variants) only counts through an explicit feed query such as `?format=rss`, and heuristic links differing only by query collapse to one;
4. platform conventions: the page URL with `.rss`/`.atom` appended (Reddit, Mastodon, Discourse, Lobsters, GitHub), then `feed`, `rss`, `feed.xml`, `atom.xml`, `rss.xml`, `index.xml`, `feed.json` inside the address's own directory. A final segment is a document only with a document extension (`.html`, `.php`, `.xml` …), so `@tim.oreilly` is a directory. A sub-path never walks up to the host root, so an address on a shared platform host cannot resolve to the platform's site-wide feed. This is the route for a home page behind a bot wall whose feed is open (Ars Technica's home page answers 405 with a human-verification page; `/feed` is RSS). Bot walls and challenges are never bypassed and the User-Agent is not disguised.

One HTML page met on the way (a feed index page) may contribute its own links. Discovery is bounded to 10 fetches and a 20 s wall clock, checks cancellation between candidates, and stops at the first verified feed. A public page cannot steer the saver at a private/loopback literal address. Offline/network failure, 408, 429 and 5xx never start extra requests; a bot-walled (403/405) or missing page may.

The configured address stays the user's identity (cache key, endpoint fingerprint, sharing); the verified feed is stored on the cache record as `resolved_url` together with *its* ETag/Last-Modified. Steady refreshes are one conditional request to that feed, exactly as for a directly entered feed. Discovery runs again only when the stored feed is gone (404/410) or no longer serves a feed; other failures are ordinary retained-last-good failures under backoff. The seeds for rediscovery are the configured address and the last-good feed's own site link, so a feed that moves is found again from the site that published it, including a directly entered feed that later dies. An empty but real feed never triggers discovery. Settings TEST FEED uses the same resolver and reports the feed it found. `resolved_url` is an optional field inside cache schema 1: older records read as unresolved and older readers ignore it.

Verified on 2026-09-24 against 24 live sources: Ars Technica and its gaming section, Letterboxd (conventional path), Reddit (page suffix), The Verge, BBC News, GitHub Blog and its category, GitHub releases, YouTube, Mastodon, Bluesky, micro.blog, Lobsters, Discourse, Lemmy, itch.io, tantek.com, adactio.com (its notes feed), snarfed.org (advertised), Polygon (anchor), NYT (feed index page one hop away), Daring Fireball's JSON Feed (direct) resolve in 2–5 fetches. Reuters, GameSpot and Medium bot-wall their feed paths too, and a Steam news page advertises no feed; all fail cleanly as `FeedDiscoveryError`.

Wallpaper feeds acquire their documents through this same `FeedSource` path; see § Wallpaper feeds.

## Normalized document

Supported formats, all normalized into the one model below: RSS 0.9x/1.0 (RDF)/2.0 and Atom 0.3/1.0 through `feedparser` (`core/feeds/parser.py`); JSON Feed 1.0/1.1 and JF2 feeds (the W3C Social Web JSON feed note) through `core/feeds/json_feed.py`, dispatched by sniffing a JSON object; IndieWeb h-feed pages (microformats2 `h-entry`, including value-class-pattern dates and nested `h-card` authors) through `core/feeds/hfeed.py`, which builds JF2 and reuses the same mapping. Legacy mf1 `hentry` is deliberately not read (common theme markup on sites that advertise RSS anyway). A page is only treated as an h-feed when it declares no RSS/Atom/JSON/JF2 alternate, so an IndieWeb site that also publishes Atom resolves to its Atom feed.

A normalized item contains stable identity, title, optional action URL, bounded plain-text summary/author, optional publication time, zero or more feed-advertised image candidates and zero or more non-image enclosures. No image is required for validity.

Identity precedence is explicit feed ID/GUID, then action URL, then a bounded title/time fallback. Action targets may currently normalize HTTP, HTTPS or magnet schemes, but later runtime launch capability remains separately allowlisted. Feed-advertised image candidates accept only HTTP/S. Relative links are resolved against the final feed endpoint.

Title sanitation preserves authored titles. A missing or blank title (Mastodon, Bluesky, micro.blog and IndieWeb notes; JSON Feed `content_text` posts) is derived in this order: magnet `dn=`; the entry's own text (whole sentences up to 140 characters, a too-long first sentence cut at a word with an ellipsis), with the summary continuing from where the title stopped so the two never repeat; then enclosure/URL-like path information or hostname. Machine-like separators are cleaned only on the URL fallback path. An item with no summary/description takes its summary from its first content body (`content:encoded`-only items). Podcast episode art (`itunes:image` on the item) is an image candidate.

## Last-good and health state

Every cache record contains logical source ID, endpoint fingerprint, optional immutable snapshot, persisted health, ETag/Last-Modified and schema version. Writes are atomic and use unique temporary files; malformed/oversized cache input is rejected and quarantined instead of admitted into runtime state.

A transport/parse/empty-feed failure updates health/backoff but retains the previous valid snapshot. A 304 refresh retains the exact document and marks the check successful. A storage-write failure never converts a valid in-memory generation into a source failure. Persisted failure backoff prevents restart/retry churn.

CUSTOM cache keys include endpoint fingerprint. URL replacement therefore has no path that can render the previous endpoint's snapshot. Future built-in providers may opt into endpoint migration under a stable provider cache key: an old snapshot may remain visible while a replacement official endpoint is failing, but old validators are fenced off and success advances the stored endpoint fingerprint.

## Presentation and images

`project_feed()` is pure and receives only a snapshot, display mode, limits and optionally already-validated local artwork sources. It never downloads or exposes remote URLs as render sources. Feed image URLs are only artwork candidates. Geometry does not feed back into the projection: retained QML alone decides which already-projected rows are currently visible, so resize/Edit never resets the model or republishes an image generation.

List and Grid both admit validated local artwork **per stable story identity**. A story without artwork uses its authored text-only row/card rather than suppressing unrelated cached images or reserving a broken image hole; Compact remains text-only. Grid artwork admission is per-story rather than cohort-completeness-gated. Before warming, artwork admission still compares candidates across the accepted document. Candidate identity canonicalizes scheme/host/path while ignoring query and fragment for duplicate comparison, so signed/tracked variants of the same site hero cannot masquerade as different article images. A candidate repeated across distinct items is treated as feed/site chrome rather than article identity. Distinct URLs that normalize to identical cached/downloaded image bytes are also treated as shared content; the warmer can revoke that candidate and try the next feed-advertised candidate for the affected story. Feed-contained image discovery covers Media RSS, image enclosures, ordinary/lazy HTML image attributes and `srcset`/`data-srcset`, resolving embedded relative candidates against the associated article URL when available (otherwise the feed endpoint). Because `feedparser` may sanitize modern lazy/srcset attributes before normalization, the parser also inspects only the matching summary/description/content markup from the already-downloaded XML bytes and merges those candidates into the same bounded per-entry discovery order. This companion is image-candidate recovery only: `feedparser` remains the feed/model authority, and no article HTML page is fetched.

FEEDS uses the product-wide event-driven clickability language. Semantic colour is the resting/state language. Text-dense List rows use a small inset **neutral-white** surface wash plus pointing cursor and deliberately **no row stroke**, so the affordance cannot cut through title/age rails. Grid/card and artwork boundaries keep their full semantic colour at rest and turn bright white while their admitted action is hovered. Hover performs no provider/cache work and owns no timer.

Games You Follow remains a separate Steam consumer with its own image rails/placeholders and Steam-specific cache/source ownership. The shared lesson is only that one missing optional image must not globally veto valid unrelated artwork. Do not merge FEEDS and Steam scheduling, cache authority or image admission merely because both present optional media.

Presentation treats configured item count as a **maximum**. The retained card budgets a stable footer, paints only complete List/Compact rows or Grid cells that fit the current geometry, reports hidden rows as `+N MORE`, and adapts Grid columns and visible rows to the current independent content extent. Layout is measured from the actual padded authored `OverlayCard` content surface, not the uniformly scaled outer item pixels; otherwise a parent scale below 1 creates an unreachable lower band in Edit. When the current Grid fills its row capacity, the already-admitted rows consume the harmless vertical remainder instead of leaving a second dead strip. `feeds_custom_1` uses the ordinary shared `content_extent` contract on both horizontal and vertical axes (320×180 logical floor): side handles may change one axis without forcing uniform scale, while the ordinary outer scale remains a separate editor intent. Reflow is presentation-only and performs no feed/image I/O or Settings writes until the existing Edit session saves. The QML deliberately does not own a `ListView`, `GridView`, `WheelHandler` or internal scroll position, preserving Edit-mode wheel/resize authority.

Custom 1 also uses the shared CUSTOM-child geometry owner rather than a FEEDS-specific editor. Its stable editable roles are `header`, `refresh`, `articles` (the repeated article region as one semantic group), `artwork` and `overflow`. Volatile article IDs/titles are never persistence keys. The single `artwork` role is a repeated-geometry contract: its representative Edit target sits over the first actually painted local image (including List's authored narrow-width suppression), while every visible List/Grid image consumes the same freeform width/height/offset factors. Grid cards reflow title/summary into the largest usable left/right/above/below region around that image and use bounded text fitting, so changing artwork geometry changes useful text room instead of preserving a fixed landscape slot. Image pixels are never mirrored. The common edit session therefore owns detach, resize/move, alignment flip where admitted, Reset, undo, lock, snapping, persistence and containment; FEEDS only projects the validated child-geometry payload into its retained QML targets. Outside Edit there is no additional child scheduler or geometry I/O.

The `header` role is the same shared `BrandedHeader` primitive used by the other ordinary families, not a FEEDS-local renderer. It receives the same semantic header fill/border/text roles as the established branded-header families. Publisher feed-title metadata is a separate small bounded subtitle below the pill rather than a secondary line inside it; it is a per-slot optional presentation setting (default on). The subtitle is set in points, so its box is the subtitle font's real line height (QML `FontMetrics`), never `fontSize` read as pixels: a shorter box lets vertically centred glyphs climb out of it toward the pill. The subtitle's presence follows the feed's own title, which is content, so it only reflows the card's interior; it never reaches `basePreferred*`, the preferred size or the role list (headless gate in `tests/test_qtquick_feed_component_load.py`). Header left/right alignment is the one widget-wide semantic orientation intent: branded content/corner, refresh rail, Grid ordering, List artwork/text/age rails and overflow alignment mirror together, while glyphs and image pixels remain normally rendered. The configured-name monogram is a cached QPainter wireframe/segment image generated once per semantic config and handed to QML as a local data URI. It has no emoji/font-glyph runtime dependency and no QML Canvas/timer. When two or more live CUSTOM slots share a monogram initial, each carries a small ordinal (slot order among enabled, configured slots) drawn by the same cached segment painter in the tile's corner, with the letter reduced to make room; a unique initial has no ordinal.

## Wallpaper feeds

Wallpaper feeds (Settings → Sources → Wallpaper Feeds, `sources.rss_feeds`) are a separate product from the FEEDS widget. They maintain an image pool for wallpaper rotation, not a list of stories, but acquire through the same core. `sources/rss/coordinator.py` owns the pool.

- **Documents.** Each feed is a `FeedSource`, which gives conditional requests, standards-based discovery, persisted backoff, a last-good document and bounded DNS. RSS, Atom and JSON Feed are parsed as feeds. Anything else structured goes to the JSON image-listing adapter (`sources/rss/json_listing.py`), which reads listings by shape and never by site (e.g. Reddit `.json`, Wallhaven's API). Reddit hosts share the Reddit widget's request quota.
- **Images.** `sources/rss/image_fetch.py` streams each image through the shared vetted public-image path (`core.feeds.artwork_transport.iter_public_image`). An image is admitted only when it fills every connected display in fill mode without upscaling. A too-small image is refused from its header after a few kilobytes, and refusals are remembered (`MAX_REJECTED_URLS`, re-judged after `REJECTED_URL_TTL_DAYS`). A far larger image is stored right-sized once.
- **Pool and rotation.** The pool target is `TARGET_TOTAL_IMAGES`, with an on-disk byte cap. Once per process session, up to a third of the pool is replaced, stale images first. An old image is retired only after its replacement is on disk. Passes run on the engine's existing IO-lane task; there is no scheduler, timer or worker process of its own (the never-started RSS worker process was removed on 2026-09-25).
- **Settings actions.** *Just Make It Work* replaces the list with `sources.rss.constants.DEFAULT_RSS_FEEDS` (its tooltip is generated from that list). *Clear Cache* deletes the pool; new images arrive on the next pass. *Save Feed Images To Disk* copies every kept image to a chosen folder and never deletes from it. The ratio slider balances local folders against feeds.
- **Defaults.** `DEFAULT_RSS_FEEDS` holds sources measured to publish images well beyond 1080p (NASA Image of the Day, NASA JPL Photojournal, Wallhaven), plus Bing for 1080p setups. Flickr and Wikimedia are deliberately absent. Existing user lists are never rewritten.

## Cache maintenance

The Feeds cache is explicit under the canonical application cache root (`cache/feeds`). User-facing cache maintenance may clear this last-good data; it does not clear CUSTOM URLs/names or any settings/credential material. Feed cache records are bounded by schema and file size. The `FeedArtworkCache` is invoked by Custom 1’s existing shared source-owner IO lane below `cache/feeds/artwork/`. It uses URL-hash local filenames, verified normalized PNGs, 256-file/128-MiB worker-write eviction and protection for published images of currently observed source generations. One warm may accept at most four newly network-owned story images and may try at most eight bounded feed-advertised candidates, all inside the existing shared eight-second batch deadline. Before network work it scans every candidate for a valid local cache hit, so a failed preferred URL cannot hide a cached lower-ranked fallback. The `core/feeds/artwork_transport.py` callback pins a publicly vetted DNS answer before connecting, validates every redirect, retains HTTPS hostname verification and bounds response bytes/time/cancellation. Accepted article text publishes cache-first; one event-admitted optional artwork batch publishes a retained local-file image generation atomically. An unchanged source document does not trigger repeated missing-image requests on every normal source refresh. The runtime has no new image timer, separate downloader or GUI-thread file validation; multi-source eviction is proven (`tests/test_feed_artwork_multisource.py`) and stalled DNS is bounded (see Transport). Eviction is least-recently-used: every file a warm selects, including a cache hit, has its age refreshed. Protection is read when a warm evicts, from the family owner's immutable set of every currently published image (replaced whole on the GUI thread whenever a result is accepted or a source is pruned), never a submit-time copy, so a source that publishes meanwhile, including an older cached file, is never evicted from under its card. A source retired during its image job is cancelled before it evicts anything.

## NEWS durability rule

`core/feeds/news_candidates.py` is a research/probation catalog only. It is not product authority and importing it does not enable a NEWS widget. A category cannot be promoted until at least two independent no-signup providers have repeatedly passed the native `tools/feed_probe.py` path. Provider health describes technical reachability/parser viability only; it is not an editorial score.

The shipped architecture must tolerate endpoint death by changing the provider descriptor, not by changing the user's widget identity. Third-party RSS recreation services, API-key sources and page scrapers are outside the intended durable baseline.

## Runtime ownership

The runtime uses one `_FeedFamilyOwner` per active runtime generation (or helper-manager fallback in isolated tests). Retained cards hold lightweight leases. The owner keeps one earliest-due deadline across active sources and deduplicates CUSTOM acquisition by endpoint fingerprint, so the same feed used on multiple displays or future CUSTOM slots shares last-good state and network cadence while each card keeps independent presentation settings.

Cadence is projected from **currently active** leases; retiring a short fast lease cannot permanently ratchet the shared source. An idle source releases its HTTP transport state while retaining the immutable accepted result. Reactivation before the next due time reuses that result without rereading disk merely to recreate source state. Cache-only admission is first; a fresh cache schedules the future due deadline without importing/constructing the HTTP stack, while an empty cache proceeds to one bounded refresh. Persisted backoff owns subsequent failure timing.

Browser actions remain HTTP/S-only at both presentation admission and the presentation-neutral product-action boundary; later magnet/torrent capabilities require separate allowlisted actions.

Each source state also has a job-scoped cancellation event. When its last **active** lease disappears, that event cancels queued/streaming work without stopping other sources owned by the same family generation. The worker checks it before source I/O and through bounded transport reads; source refresh also checks after transport/parsing and before cache writes, so cancellation is not persisted as provider failure or backoff. A canceled completion cannot publish, and an endpoint with no remaining attached leases is pruned after its worker finishes. A shared endpoint remains active while any of its leases is still active. An inactive attached lease may retain an immutable last-good result for reactivation without keeping an HTTP session open. Source sessions are closed only after their in-flight worker exits, not from a GUI-side `stop()` during an active read.

Worker callbacks are tagged/fenced to the runtime generation and presentation consumers are weakly attached. Presentation retirement stops its lease and detaches the callback; the runtime-service manager remains final lifetime authority. QML owns no timer, network operation or remote image source.

The runtime admits all four CUSTOM slots with event-driven optional local artwork. Source-specific in-flight cancellation/pruning is part of the shared family owner: the last active lease cancels that endpoint without disturbing unrelated active endpoints, identical endpoints share one source, and artwork eviction protection covers every published source (`tests/test_feed_runtime.py`, `tests/test_feed_artwork_multisource.py`, `tests/test_feed_custom_slots.py`). NEWS IDs stay non-runtime until their provider layer lands.

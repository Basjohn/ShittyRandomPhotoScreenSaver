# Extruded Bubble | Execution & visual acceptance runbook

**Read alongside `Current_Plan.md` §4B, `Target.md`, and `Investigation.md`.** This is the test-and-evidence protocol for the **single live queue** in §4B, not a second backlog or a declaration that any candidate is accepted. Original D/B/C/A/S/F/L/P and other issue records remain authoritative for symptoms, specific constraints, failed approaches and source details. Every `[ ]` / `[~]` remains open until the operator or a capable local visual agent examines the required evidence and explicitly accepts the result. Keep all existing rejection details visible; don't replace them with a shorter success story.

## A. Evidence protocol: must pass before a visual claim

1. **Fix the comparator.** Record the exact audio-file identity, playback start/stop, capture block size (notably 256 and 512), presentation FPS/DPR/card dimensions, preset name and *current mutable* preset values, light type, camera transform/FOV, and selected Settings. Use `logs/visualizer_recordings/anything_mixed2.jsonl` plus the operator's Ragdoll, Heavy and quieter passages where accessible. If those files are absent locally, report them as unavailable; never synthesize a replacement and call it a same-recording comparison.
2. **Synchronize 2D and EB.** On the identical source recording, mark the same sample-time or timestamped musical events. Pair `2D Bubble` and `Extruded Bubble` at those times, preferably with screenshots/contact sheets **and** short high-frame-rate captures. Track per-ID target radius, displayed radius, centre XYZ, physical radius, alpha, bubble kind, population/admission state and the actual pixels. The 2D behavior is a minimum *reactivity-scale and temporal role* oracle, **not** a request to duplicate its artistic geometry.
3. **Trace the single ownership chain.** Input/bands/AGC → logical tick → per-ID physical and display state → snapshot/instance/uniform → final HDR/bloom/defocus pixel. State where a mismatch first appears. Synthetic numerical tests, GLSL compilation, a single photo, or an apparently convincing camera angle are **not** sufficient by themselves.
4. **Controlled A/B.** Hold audio, card dimensions, camera and all unrelated controls steady; vary **one** parameter. Include idle → soft → loud → different loud/fast → soft → silence, as well as startup, pause/resume, preset changes and light-mode switches where relevant. A control must demonstrate perceptible impact *during continuous playback*, not merely stopped-versus-playing.
5. **Motion evidence, not FPS alone.** Compare frames on the same clock, annotated with sample time; inspect 90-Hz frame sequences for discontinuities, bands, missing instances, shader aliasing and speed changes. A still can establish geometry and appearance but **cannot** establish a fade, bounce, judder or intra-song response. Record GPU frame/p99 and logical-age impact only with existing bounded diagnostic options, not new observers.
6. **Disposition.** For each gate record `Observed / Expected / Reproduction / Evidence location / Source owner / Focused tests / Remaining competing cause / Operator or visual-agent decision`. On failure, retain `[ ]` or `[~]` and add the new evidence to the existing item. On a candidate source fix, retain `[~]`. Do not promote to `[x]` without a specific visual approval, even if all code tests pass.

**Costs and authority:** no additional polling, source clock, render scheduling authority, camera-relative populations, screenshots on every frame, thread worker, global GC policy change, lifecycle timeout increase, hidden environment-variable configuration, or preset overwrite. Only minimal failure-scoped instrumentation, switched off when not needed. Do not request a full chunked suite, build or frozen test for routine checks. On the operator's Windows tree, use the repo-root `.venv\Scripts\python.exe` with focused pytest and the existing no-environment test fixture only when compatible with that test; do not set or mutate environment variables. The original 2D Bubble contract remains intact.

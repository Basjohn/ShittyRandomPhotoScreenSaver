## Active Tasks

The 2026-07-16/17 post-overhaul logs are now authoritative. They cover two mixed `165/60 Hz` Normal lifetimes with transitions, Settings and CUSTOM rebuilds, plus a 75-minute single-display `60 Hz` MC lifetime. The migration is structurally healthy: no visible regression was reported; normal runs created no legacy child surface; shader/program lifecycle, visualizer render-failure, and FBO-churn counts remained zero; and the long MC compositor stayed near its 60 Hz target. Phase E nevertheless failed its performance-promotion objective. The ordinary mixed-display run remained roughly as expensive as before, the rebooted run was materially better but not representative, and the long MC run accumulated severe visualizer/event-loop cadence pressure while transitions were idle. New widget work is frozen until this foundation earns repeatable ordinary-background headroom without lowering fidelity, smoothing, reactivity, source cadence, or transition cadence.

### Performance Foundation Promotion

Fresh lifetime evidence is intentionally separated rather than blended across process restarts. The ordinary-background mixed-display lifetime averaged/peaked about `93.5/125.5%` app CPU and delivered high-refresh compositor windows around `104-121.5 FPS` against `165 Hz`, despite paint durations usually remaining below `14 ms`. The post-reboot mixed-display lifetime improved to about `82.0%` average CPU and reached roughly `153 FPS` on the high-refresh display, proving environment state materially changes the result but not providing a realistic operating assumption. The 75-minute MC lifetime averaged `58.0%` app CPU (`83.0%` p95), submitted compute work at `93.4/s`, kept ResourceManager GL registrations nearly flat (`22 -> 24` observed), and showed no compositor visualizer render/FBO failure, yet accumulated `1,710` parser-recognized visualizer timing warnings and repeated `80-118 ms` latency while compositor transitions were idle. This is shared CPU/GIL/event-loop pressure, not evidence that the compositor shader or GPU is saturated.

The first remediation pass removes measured diagnostic and empty-scene overhead without changing runtime cadence: task throughput statistics now update a small locked snapshot directly instead of scheduling a UI drain for every submit/completion; the unused 250 ms UI stats publisher/triple buffer is retired; inactive compositor visualizer scenes no longer open a QPainter session; hidden staggered displays report a pending compositor rather than a terminal normal-path error; and `--usage` now owns nonblocking process/system CPU-time deltas plus bounded top-thread attribution. The parser partitions application lifetimes and orders dated rotations correctly, so resource slopes and compute rates cannot cross process starts.
